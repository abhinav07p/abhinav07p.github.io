TrialMatch AI

Agentic multi-modal clinical trial matching

TrialMatch AI takes a patient profile entered as text, voice dictation, or a medical image and runs it through a seven-agent reasoning pipeline. It extracts medical entities, retrieves candidate trials from live government APIs and a vector store, parses eligibility criteria into structured rules, cross-checks medications against FDA labels, and returns ranked matches with criterion-by-criterion reasoning and source citations.

The problem

Clinical trial matching is broken because no human can cross-reference every patient against hundreds of trials with dozens of eligibility criteria each. Figures below are the ones cited in the project README.

~5%of adult cancer patients enter clinical trials
86%of trials miss enrollment timelines
20%of trials close for low enrollment
$8Mpotential cost per day of trial delay
The patients exist and the trials exist. They never find each other. It is a matching problem hiding inside a healthcare system, which is exactly where an agentic pipeline can help.

System architecture

Three input paths merge into one patient profile, then flow through retrieval, parsing, safety checking, and scoring.

Every recommendation ships with a full audit trail. The system is designed to fail loudly: criteria it could not evaluate are flagged as NOT EVALUATED instead of being hidden behind a confident score.

Five generative AI components

Each one is implemented and wired into the pipeline.

Three operating modes

The same app runs anywhere, from a grader’s laptop to production.

🎯 Demo mode

No setup. Pre-loaded patients and cached trials, so everything works offline with no keys.

🦙 Ollama mode

Local LLM through Ollama (Mistral, Llama 3, Gemma 2, and LLaVA for images). Free and private.

🔑 API mode

OpenAI or Anthropic keys for the best quality on production runs.

Fine-tuning workflow

Optional by design: without trained weights the app falls back to LLM-based extraction. With them, the README reports inference about 14× faster and free.

Model 1 · Criteria parser (BioBERT)

Review the JSONL training data, run the Colab notebook on a free T4 GPU, download the zip, unzip into fine_tuning/models/criteria_parser/, and the app picks it up in the sidebar.

Model 2 · Medical NER

The same loop for entity extraction: JSONL data, Colab training, drop the weights into fine_tuning/models/medical_ner/. The app scans for config.json to auto-detect.

Multimodal input and output

🎤 Voice in

Upload audio or record in the browser. Whisper transcribes, an LLM extracts structured medical entities, and they merge with any existing profile.

🖼️ Documents in

Lab reports, pathology reports, and prescriptions are read by OCR, then a vision model structures lab values, biomarkers, and medications.

🔊 Audio out

A spoken summary of the top matches, downloadable as MP3 through gTTS or OpenAI TTS.

Evaluation framework

A built-in benchmark runner scores the pipeline against gold-standard data. These are the targets the project is measured against.

MetricTargetWhat it measures
Retrieval recall≥ 85%Of all truly eligible trials, how many were found
Retrieval precision≥ 75%Of returned trials, how many were actually eligible
F₂ scoren/aRecall-weighted (β = 2), because missing a match is worse than a false alarm
Exclusion accuracy≥ 90%When the system says excluded by criterion X, is that correct
Faithfulness≥ 0.85Does the explanation match the structured reasoning trace (LLM-as-judge)
Criterion coverage≥ 70%Share of criteria actually evaluated rather than skipped
Voice word error rate≤ 15%Accuracy on medical dictation
Image OCR accuracy≥ 90%Correct field extraction from lab report images

Ethics and privacy by design

No real patient data

All profiles are synthetic and HIPAA-safe. Only condition-level queries reach external APIs, and patient data never leaves the local machine.

Public sources only

Every API is public and government-maintained. No proprietary data and no scraping.

Transparent reasoning

Every match or exclusion cites the exact criterion and its data source.

Fail loudly

Unevaluated criteria are flagged as NOT EVALUATED. Trial diversity data is surfaced and the system never filters on demographics.
